# OpsQuality 评测体系叙事说明

本文档用于解释当前 OpsQuality 可视化评测体系的叙事逻辑、指标边界与交付口径。面向场景是：构建 MLLM Post-Training 所需高质量数据集的数据 Pipeline，并基于 Ray 数据并行处理框架对多模态数据处理算子进行质量评估。

## 1. 核心结论

当前评测体系的合理定位是：

> 以数据 Pipeline 的算子为评估单元，对每个算子处理前后的数据产物进行质量证据采集，判断数据是否仍然满足 MLLM Post-Training 的可用性要求。

因此，当前 dashboard 的核心是回答三个问题：

1. 算子是否产出了预期的数据结构和中间产物？
2. 算子处理后，文本语义、图文关系、视频片段与采样帧关系是否保持稳定或得到改善？
3. 哪些指标已经可以真实评测，哪些指标因为缺少模型、字段或下游任务环境而只能标记为不适用或受阻？

换句话说，dashboard 应展示“数据质量证据链”。

## 2. 为什么需要 trend 图

Trend 图在本体系中不是为了证明指标天然会随 pipeline 单调变好。它的作用是做“跨模态语义质量漂移”评估。

MLLM Post-Training 数据 Pipeline 通常由多个清洗、增强、采样、描述生成、证据物化算子串联而成。单独看最终数据集分数，会掩盖质量变化发生在哪个环节；而按算子阶段绘制 trend，可以回答：

- 哪些算子不影响语义关系稳定。
- 哪些算子会有预期内的质量变化。
- 哪些算子引入了非预期漂移。

因此，trend 图的合理解释是：

> 对每个 pipeline stage 做阶段性快照，比较同一批样本在算子执行后的质量信号，定位数据语义质量漂移来源。

当前 `quality/test/outputs` 下的 trend 输出文件为：

| 输出文件 | 展示问题 | 判别 |
| --- | --- | --- |
| `text-image-alignment-trend.csv/svg` | 图文语义关系是否被后续算子破坏 | 文本规范化、重复移除等文本清理不应破坏图文对齐；语义遮蔽或强视觉变换会降低图文匹配。 |
| `text-image-alignment-model-selection.csv` | 图文评测裁判模型是否可信 | 在使用本地 VLM 做图文一致性评分前，先用正例、负例、部分错配和噪声样本校准候选模型，避免直接采用未校准裁判。 |
| `image-video-alignment-trend.csv/svg` | 视频片段和采样帧的关系是否经图像算子后仍稳定 | 翻转、裁剪、Canny 等图像变换会不同程度改变视觉表征；trend 用来区分“语义仍对齐”和“表示明显漂移”。 |
| `image-video-alignment-segments.csv` | 视频片段锚点和 embedding 来源是否可追溯 | 记录 segment clip、anchor sample frames、embedding 模型和状态，支撑视频-帧对齐分数的可解释性。 |
| `schema-aligned-text-cleanup-quality.csv/svg` | 文本清理是否带来可度量收益 | 用 before/after 对比证明文本清理降低重复率和残留非规范模式。 |

需要强调：trend 图只对“会经过多个 stage 的关系型质量指标”有意义。例如文本噪声、图文对齐、视频-帧对齐适合趋势化；

还需要区分两类 VLM：`text-image-alignment-model-selection.csv` 中的本地 VLM 是“数据一致性裁判”，用于给图像-caption 对 or 提供的 图像-文本对 进行打分
## 3. 评测体系的分层叙事

这一套评测体系的设计起点是“MLLM Post-Training 数据 Pipeline 最容易在哪些环节失真”。数据从原始文本、图像、视频进入 pipeline 后，会经历清理、增强、采样、描述生成、证据物化等多个算子。每个算子都可能带来收益，也可能引入新的风险：字段变了、语义变了、图文关系变了、视频时间锚点丢了、生成的监督信号没有证据支撑。

因此，评测体系的重点落在了链路的数据质量风险上。假如链路出现了数据失真的问题，那么多模态数据便会没有意义；例如字段结构不稳定时，语义评测会读错对象；文本语义已经被清洗算子改坏时，再看图文相似度也无法判断到底是图像不对齐，还是文本已经变质；QAE 没有证据引用时，下游 LLM judge 的分数也无法解释。

所以当前体系按五个问题展开：

1. 数据还能不能被消费。
2. 数据自身语义有没有被破坏。
3. 多个模态之间的关系是否仍然成立。（核心问题）
4. 有意引入的扰动是否受控。
5. 生成出来的训练监督是否有证据支撑。

这五层共同服务一个目的：把“数据是否适合进入后续 MLLM Post-Training”拆成可审计、可定位、可解释的证据链。

### 3.1 第一层：先建立数据合同，而不是先谈质量分

Pipeline 评测的第一层必须是结构层，因为 MLLM 训练数据不是一张孤立图片或一段孤立文本，而是一组带字段约定的样本。文本、图像、视频、采样帧、片段、描述单元、QAE 三元组都需要以稳定 schema 传递给后续算子和训练系统。

这一层的目的不是证明数据“好”，而是证明数据“可被评测、可被追踪、可被消费”。如果算子输出字段缺失、字段语义不一致、before/after 无法配对，后面的质量评估都会变成偶然读到了某个字段，而不是可靠审计。

因此 dashboard 中的“算子 x 指标证据矩阵”首先承担的是数据合同说明：哪些算子应该产生哪些可评测产物，哪些评测在该算子阶段本来就不适用，哪些失败是前置条件缺失而不是质量低。这个矩阵的价值在于防止误读：不是每个指标都应该覆盖每个算子，也不是每个空分数都代表质量问题。

### 3.2 第二层：再判断处理是否改变了样本本意

数据清理和规范化的核心矛盾是“去噪”和“保义”。Post-Training 数据需要干净，但不能为了干净而改变样本原本表达的事实、主体、意图或描述范围。文本清理、格式规范化、重复移除、拼写修正等算子都属于这一类：它们应该降低噪声，而不是创造新语义。

这一层回答的是：算子有没有在“修数据”的过程中改写数据。它也是后续跨模态评估的前提。如果文本自身已经被清理坏了，图文不一致可能不是视觉链路的问题，而是文本链路提前损坏。

因此 before/after 展示的目的不是炫耀清理后的文本更整齐，而是证明一个约束：质量收益来自噪声下降，而不是来自语义漂移。文本清理类图表应该围绕这个约束展开。

### 3.3 第三层：把单模态质量推进到跨模态关系

MLLM Post-Training 数据的关键价值不在于单个模态分别正确，而在于不同模态之间能形成可学习的对应关系。图像和文本要讲同一件事，视频片段和采样帧要锚定同一时间范围，描述单元要对应片段或事件，QAE 要能回到证据来源。

这一层的目的，是从“样本本身没有坏”推进到“模态之间的监督关系没有坏”。这也是为什么 trend 图有存在价值：跨模态关系会在 pipeline 中被多个算子间接影响。文本规范化看似只改文本，可能影响图文匹配；图像增强看似只改图像，可能影响图文或视频-帧对齐；视频采样看似只是抽帧，实际决定后续描述和 QAE 的视觉锚点。

因此跨模态 trend 不是为了证明分数单调上升，而是为了定位关系漂移：哪个 stage 之后关系开始下降，下降是否符合算子预期，是否需要改变该算子的用途、参数或下游消费方式。

### 3.4 第四层：区分“有益增强”和“破坏性扰动”

数据增强在训练数据 Pipeline 中是必要的，但增强本质上是主动引入扰动。它和清理算子不同：清理希望尽量靠近原始语义表达，增强则允许表面形式发生变化，前提是变化可控、意图明确、不会破坏训练所需的语义关系。

这一层的设计目的，是把“变化”拆成两类：期望内变化和非期望漂移。比如翻转、裁剪、边缘化可能导致像素结构明显变化，这并不天然代表质量下降；关键是主体语义、可学习关系和训练标签是否仍然成立。

所以视觉增强的展示不能简单说“分数变高/变低”，而要解释变化类型：结构变了多少，语义是否仍稳定，对齐关系是否还能被下游使用。这样才能把鲁棒性评测从“看一个指标数值”转化为“判断扰动是否仍在设计边界内”。

### 3.5 第五层：最终回到训练监督是否可信

MLLM Post-Training 最终消费的不是原始数据本身，而是由 pipeline 组织出来的训练监督：caption、描述单元、问答、证据引用、时间片段、视觉锚点等。前四层证明了数据和关系没有明显坏掉，但还没有证明这些监督信号能被信任。

这一层的目的，是把 pipeline 产物从“格式上可用、关系上大体对齐”推进到“可以作为训练监督”。对于 QAE、视频描述、证据引用类数据，最重要的问题不是它们是否存在，而是它们能否被文本证据、视觉证据和时间证据支撑。



## 4. 与交付需求的覆盖关系

原始交付需求提到五个方向：语义一致性、跨模态对齐质量、生成保真度、鲁棒性测试、任务特定性能。当前实现需要按“已覆盖、部分覆盖、明确不纳入”来讲。

| 需求方向 | 当前覆盖状态 | 当前实现/证据 | 交付口径 |
| --- | --- | --- | --- |
| 语义一致性 | 已覆盖 | `text_semantic_preservation`、`text_normalization_validity`、`text_noise_contamination` | 覆盖文本清洗前后语义保持、规范化残留和噪声下降。 |
| 跨模态对齐质量 | 已覆盖/部分覆盖 | `image_text_alignment`、`video_image_alignment`、`chair_object_hallucination`、`coherence_score` | 覆盖图文、视频片段-采样帧、视觉主体-文本主体、多粒度描述连贯性。QAE grounding 因缺少 LLM client 受阻。 |
| 生成保真度 | 当前不成立 | 不将 PSNR 作为主指标 | 当前算子系统并非图像/视频重建或生成保真链路，没有可定义的 reference target。PSNR 只适合像素级重建/压缩场景，不适合 caption、采样、增强、QAE 物化的保真度叙事。 |
| 鲁棒性测试 | 部分覆盖 | `visual_robustness`、`visual_transform_consistency`、SSIM、embedding drift | 当前覆盖受控视觉变换后的结构和语义稳定性；尚未覆盖完整对抗样本鲁棒性和分布偏移适应。 |
| 任务特定性能 | 当前忽略 | 无图文对比损失、图文匹配损失、下游任务分数 | 该类评估需要下游 LLM/VLM 或训练任务环境。对方未提供下游模型和任务协议，因此当前实现不纳入。 |

## 5. 为什么“保真度”当前不成立

保真度通常要求存在明确的输入、生成结果和参考目标，例如图像超分、图像生成对齐参考图等场景。此时 PSNR、SSIM 等像素级指标才有稳定语义。因此，我们忽略了保真度的评估和设计。

 `visual_robustness.structural_similarity_mean` 可以作为视觉增强的结构变化诊断，但不能替代生成保真度。

## 6. 为什么“任务特定性能”当前忽略

任务特定性能通常需要下游任务闭环，例如：

- 用清洗后的数据训练/微调 LLM 或 VLM。
- 在图文检索、VQA、captioning、grounding、instruction following 等任务上评测。
- 计算图文本对比损失、图文匹配损失或下游 benchmark 指标。



## 7. Dashboard 推荐讲述顺序

建议汇报 dashboard 时按以下顺序讲：

1. 背景：MLLM Post-Training 数据质量取决于 pipeline 中每个算子的输出，而不是最终单点分数。
2. 评估单元：以 Ray Dataset 快照和 after-operation 抽样行为基本评估对象，比较 before/after 或 stage-to-stage 变化。
3. 矩阵：先说明哪些算子能被哪些指标评测，哪些不适用，哪些受阻。
4. 文本清理卡片：证明噪声下降、规范化残留下降，同时语义保持。
5. 图文对齐 trend：证明文本清理不破坏图文关系，强视觉/语义扰动会导致关系下降。
6. 图像增强卡片：证明增强成功、语义基本稳定，同时结构变化被 SSIM 捕捉。
7. 视频-帧对齐 trend：证明视频采样和图像变换后的片段-帧关系可追溯。
8. 视频描述连贯性：指出模板化描述会被 coherence score 暴露。
9. QAE grounding 卡片：明确展示 blocked 状态，说明缺少真实 `llm_client`，不是低质量得分。
10. 边界说明：保真度当前不成立，任务特定性能因缺少下游 LLM/VLM 暂不纳入。

## 8. 当前体系是否完整

如果以“MLLM Post-Training 数据 Pipeline 的算子级质量证据体系”为目标，当前体系是基本完整的最小闭环：

- 有统一评测入口：`OpsQualityAssessor`。
- 有 pipeline 侧接入点：`OpsQualityPlugin`。
- 有结构化结果：`MetricResult`。
- 有覆盖矩阵：说明 metric 与 operation 的关系。
- 有 before/after 和 stage trend：解释质量变化来源。
- 有 blocked / not_applicable 状态：避免伪造不可评测结论。

但如果以原始需求中的所有指标方向逐字验收，当前体系不是完整全集：

- 保真度不成立，不能报告 PSNR 型生成保真结论。
- 任务特定性能未实现，因为缺少下游 LLM/VLM。
- 对抗鲁棒性和分布偏移适应只覆盖了受控视觉变换代理，尚未形成完整 adversarial/OOD benchmark。
- QAE grounding 接口存在，但真实 LLM judge 链路缺失。

因此，推荐交付口径是：

> 当前交付的是一套面向 MLLM Post-Training 数据 Pipeline 的算子级质量评估与可视化证据体系，已覆盖语义一致性、跨模态对齐、文本/视觉变换稳定性、视频描述连贯性以及 QAE grounding 的接口和前置条件管理。生成保真度和任务特定性能不在当前实现范围内，原因分别是现有算子系统没有可定义的生成参考目标，以及下游 LLM/VLM 未提供。

## 9. 指标到 dashboard 叙事映射

| 指标 | Dashboard 中应承担的叙事角色 | 不应过度解释为 |
| --- | --- | --- |
| `text_noise_contamination` | 文本噪声是否下降 | 全局文本质量总分 |
| `text_normalization_validity` | 规范化规则残留是否减少 | 语义正确性 |
| `text_semantic_preservation` | 清理前后语义是否保持 | 下游任务收益 |
| `image_text_alignment` | 图像与 caption 是否匹配 | 模型 caption 能力全面评估 |
| `chair_object_hallucination` | 视觉主体是否被 caption 提及且未明显错配 | 完整 CHAIR benchmark |
| `visual_transform_consistency` | 增强输出是否有效、语义是否稳定 | 图像质量提升 |
| `visual_robustness` | 受控变换下 embedding/结构漂移 | 完整 adversarial robustness |
| `video_image_alignment` | 视频片段和采样帧是否覆盖且对齐 | 视频理解任务分数 |
| `coherence_score` | 多粒度描述是否模板化重复 | 事实正确性 |
| `qae_grounding_alignment` | QAE 是否可由文本/视觉证据支撑 | 在无 LLM client 时的真实任务性能 |

## 10. 后续扩展建议

为了从“算子级证据体系”扩展为“完整交付需求全集”，建议分三步补齐：

1. 补齐 metric 触发时机：按 operation stage 控制指标运行，避免在上游字段尚未生成时产生噪声。
2. 补齐真实 QAE judge：由对方提供 LLM/VLM client、调用协议和评估阈值后，启用 `qae_grounding_alignment` 的真实裁判链路。
3. 补齐下游任务闭环：提供下游 MLLM 训练或评测任务后，再接入图文对比损失、图文匹配损失、VQA/captioning/grounding 等任务指标。

在此之前，dashboard 应坚守当前边界：只展示能够由真实算子输出、真实本地模型或明确失败前置条件支撑的评测证据。
